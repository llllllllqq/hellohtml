# 文本对比器 · Text Diff

一个**零依赖、纯前端、完全离线**的单文件文本对比工具：把两段文本分别粘进左右两栏（或打开两个文件），逐行对比、标出新增和删除，并统计变更行数。所有内容只在浏览器内存里处理，不上传、不联网。

[text-diff.html](text-diff.html)（约 53 KB）就是全部代码，没有任何 CDN、第三方库或运行时依赖。

## 功能

- **两种输入方式**：每侧都可以直接输入/粘贴纯文本后点「提交」，或点「打开文件」、把文件拖进对应半栏
- **编码自动识别与手动切换**：打开文件时按 BOM / 严格 UTF-8 校验 / 字符分布推断，识别 UTF-8、UTF-8 BOM、UTF-16 LE / BE、GBK、Big5、Shift_JIS、Windows-1252；每栏「打开文件」左边有编码下拉，默认「自动」，改成别的编码会立刻用原始字节重新解读并重新对比，编码同时显示在文件名下方
- **混合换行符可用**：CRLF、LF、CR 以及三者混排的文件都能正常分行（只按行拆分，不比较换行符本身）
- **逐行对比**：公共前后缀先裁掉，中间用 Myers 算法做行级 diff；新增行标 `+`、删除行标 `−`，左右按行对齐，缺行用空白占位
- **可选行内对比**：顶栏的「Aa 行内对比」开关，打开后逐字高亮同一行内变化的字符（中文、emoji 都按整字符处理）；默认关闭，只显示整行底色
- **增删统计**：顶部实时显示 `+N 行` / `−N 行`；完全一致时明确显示「内容一致」。没有文件时统计区保持空白，不占提示文字的位置
- **仅差异视图**：一键折叠中间连续未修改的行，只留变更和「⋯ N 行未修改」的间隙；没有差异时显示「内容一致」
- **左右 / 上下布局**：默认桌面左右、窄屏（≤760px）自动上下；手动切换后不再自动改变
- **紧凑顶栏**：布局、显示范围、横向联动、行内对比都是带图标的小按钮（手机端只显示图标，标签文字隐藏，配 `title` 与 `aria-label`），370–390px 宽度下标题、版本号和统计仍能挤在一行
- **滚动联动**：默认纵向联动；勾选「横向联动」后长行也一起横向滚动
- **每侧独立操作**：可以单独更换文件、清除一侧，另一侧保留；文件名、行数、文件大小都有显示
- **纯文本粘贴**：粘贴时只取 `text/plain`，避免把富文本格式带进对比
- **HTML 转义**：对比内容按纯文本渲染，`<script>` 之类的文本不会被当成 HTML 执行

## 用法

1. 双击 `text-diff.html`，或拖进浏览器
2. 在左栏输入/粘贴旧文本，点「提交」；右栏输入/粘贴新文本，点「提交」
3. 或点每栏右上角「打开文件」，选择要对比的文本文件；识别出的编码显示在文件名下面，如果有乱码，用「打开文件」左边的编码下拉手动换一个，会立即重新读取
4. 顶栏从左到右是：布局（并排 / 堆叠图标）、显示范围（黑色「=」全部 / 红绿「=」仅差异）、横向联动（四向箭头）、行内对比（Aa）；手机端只显示图标，长按可看提示
5. 需要看清「这一行到底改了哪几个字」时，点「Aa 行内对比」，修改的字符会在整行底色上再加深一层；再点一次关闭

没有额外的键盘快捷键；提交后输入框会清空，内容已经进入对比区。

## 数据与状态

- 文件用 `FileReader.readAsArrayBuffer` 原样读入，先识别编码再在内存里解码（BOM 会被去掉）；原始字节保留在内存里供手动切换编码时重新解读
- **不上传、不发网络请求、不写 localStorage / IndexedDB**，刷新页面后两侧内容全部清空
- 没有导出、合并或生成 patch 的功能，对比结果只用于查看

## 测试

测试在仓库根目录的 Playwright 套件里（`tests/text-diff.spec.js`），随 CI 在三种环境（桌面 Chrome / Pixel 5 / iPhone 13）运行：

- **初始状态**：两侧空编辑器、提交按钮禁用、统计区为空、桌面左右 / 移动端上下布局、无横向溢出
- **文本对比**：输入两段文本后统计 `+1 / −1`、左右行对齐、删除/新增行内容、HTML 特殊字符按纯文本显示
- **新增行**：右侧 `+1`、左侧空白占位
- **一致与仅差异**：内容一致提示、「仅差异」下的「内容一致」覆盖层、切回「全部」恢复行
- **间隙折叠**：多处修改时用「⋯ 1 行未修改」折叠中间相同行
- **布局与联动**：左右/上下切换、横向联动按钮的按下状态
- **顶栏单行**：手机端只显示图标，行内对比按钮可见，统计出现后顶栏仍是一行（高度 < 44px）
- **打开文件**：两个文件读入后的文件名、行数、统计和差异行
- **编码识别**：GBK 文件自动识别为 GBK、内容正确；手动改成 UTF-8 后用原始字节重新解读、切回「自动」恢复；文件信息里显示当前编码
- **换行兼容**：CRLF / LF / CR 混排文件分成 4 行；带 BOM 的 UTF-16 LE 文件识别为 UTF-16 LE 并正确分行
- **行内对比**：默认关闭、`aria-pressed` 正确；打开后只高亮变化的字符且未变化字符不丢失；中文、emoji、`<` `>` 都按纯文本逐字处理；关闭后恢复整行底色；「仅差异」视图下同样生效
- **行内对比边界**：2000 字长行只改末尾一个字仍能逐字高亮；整行几乎全改时退回整行高亮，不报错也不卡死

## 已知限制（如实说明）

- **编码识别是启发式**：无 BOM 的短文本（尤其是几个字节的 GBK / Big5 / Shift_JIS）可能猜错，猜错时用编码下拉手动指定即可；浏览器不支持某个编码时（极旧版本）会退回按 UTF-8 解读，显示乱码
- **行级对比 + 可选行内**：默认只标到整行；打开「Aa 行内对比」后，成对修改的行才有逐字高亮，纯新增 / 纯删除的行仍然是整行
- **行内对比会自动降级**：一行前后缀裁剪后仍有超过 400 万对字符要比较（基本等于整行重写）时，跳过字符级比较、保留整行高亮；一次渲染的行内比较总量上限是 800 万对，超出部分同样退回整行高亮。这是为了防止超长行把页面卡死
- **末尾换行不参与对比**：`splitLines` 会丢掉最后一个空行，所以「文件末尾有没有换行」的差异看不出来
- **换行符不参与对比**：CRLF / LF / CR 都按行拆分，不比较换行符本身
- **超大差异会降级**：Myers 有最大编辑距离上限，超过后中间段退化为「整段删除 + 整段新增」，结果仍正确，但不够细；超大文件也会受内存和渲染速度限制
- **只支持两个文件、纯文本**：不做二进制、编码转换、三方合并、导出 patch
- **手动布局不会记忆**：手动切过「左右/上下」后，窗口缩放不会再自动切换；刷新页面恢复默认
- **提交后输入框清空**：文本已进入对比区；想改只能重新输入或清空后重来
- **大文件渲染**：整份 diff 一次性生成 DOM 行，特别大的文件可能卡顿
- 不支持 IE

## 浏览器兼容

| 浏览器 | 最低版本 | 卡在哪 |
| --- | --- | --- |
| Chrome / Edge | 55 | 保守下限；`Map` / `Set`、`Int32Array.slice`、`FileReader`、`matchMedia` |
| Firefox | 52 | 保守下限（按特性推算） |
| Safari | 10.1 | 保守下限；`Int32Array.slice`、`FileReader` |
| iOS Safari | 10.3 | 同上 |

页面没有用 `async/await`，理论上可以支持更老的浏览器；上表是按实际用到的 API 给出的保守值，没有逐版本实测。布局只用了 flex、`max-content` 和媒体查询，没有 flex `gap` / `aspect-ratio`；`:focus` 和 `color-scheme` 只影响观感。Firefox 未纳入 CI 测试矩阵。不支持 IE。
