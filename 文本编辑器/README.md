# 文本编辑器 · Local Text Editor

一个**零依赖、纯前端、完全离线**的单文件文本编辑器：打开本地文本文件，自动识别编码和换行符，支持查找替换、撤销重做，再按指定编码和换行符保存成下载文件。所有内容只在本机浏览器内存里处理，不上传、不联网。

[text-editor.html](text-editor.html)（约 32 KB）就是全部代码，没有任何 CDN、第三方库或运行时依赖。

## 功能

- **打开 / 保存**：点顶栏最左的文件夹图标选择文件、直接拖进窗口；「保存」把当前内容下载成文件，文件名可以在顶部改。没有「新建」按钮——刷新页面就是新文档，桌面端也可以按 `Ctrl+N`
- **编码识别**：自动识别 UTF-8、UTF-8 BOM、UTF-16 LE / BE、GBK、Big5、Shift_JIS、Windows-1252
- **指定保存编码**：保存时可选 UTF-8（带/不带 BOM）、UTF-16 LE / BE、GBK、Big5、Shift_JIS、Windows-1252；目标编码表示不了的字符会先弹确认，替换成 `?`
- **重新解码**：打开文件后如果显示乱码，选好编码再点「重新解码」，用原始字节按新编码重新解读（只对已打开的文件有效）
- **换行符识别与统一**：识别 LF / CRLF / CR，混合换行会明确提示；保存时统一成选定换行符，末尾不会自动追加新行
- **编辑历史**：撤销 / 重做，普通文本最多 300 步，超过 1 MB 的文档保留 40 步；输入停顿后合并成一步，避免逐字撤销
- **查找 / 替换**：上一个 / 下一个、区分大小写、正则表达式、单次替换、全部替换；替换支持 `$1`、`$&`、`$'` 和反引号替换（插入匹配前的内容）
- **编辑辅助**：字号 10–36、自动换行开关、行号/列号、选中字符数、总行数、总字符数、编码、换行符、末尾是否有换行、是否已修改；在编辑区按 `Tab` 插入制表符（显示宽 4 个字符），不会被浏览器抢去切换焦点
- **紧凑顶栏**：打开 / 保存 / 撤销 / 重做用图标，查找替换用放大镜，自动换行用回车箭头，编码与换行下拉在窄屏显示「自 / LF」这类短标签；手机上只显示图标（`title` 和 `aria-label` 保留完整说明），顶栏压到两行以内
- **标题占位符**：空白文档时编辑区左上角以灰色显示「本地文本编辑器 + 版本号」，开始输入或打开文件后自动隐藏，不占一行高度
- **未保存提醒**：关闭/刷新页面、新建或打开另一个文件前，如果有未保存修改会先确认
- **偏好记忆**：只把字号和自动换行记在 localStorage（键名 `localedit74.prefs`），不保存正文
- **内置自检**：在地址后加 `?selftest` 会跑一遍编码往返、BOM、换行识别等自检，结果显示在页面底部（普通使用无需关心）

## 用法

1. 双击 `text-editor.html`，或拖进浏览器
2. 点顶栏最左的文件夹图标选文件，或直接把文件拖进窗口；也可以直接在新文档里输入。需要空白新文档时刷新页面（或桌面端 `Ctrl+N`）
3. 在「文件名」里改保存名，选好编码和换行符，点磁盘下载图标保存
4. `Ctrl+F` / `Ctrl+H` 打开查找替换，`F3` 找下一个，`Shift+F3` 找上一个，`Esc` 关闭

快捷键（输入框内也会生效，浏览器原生快捷键除外）：

| 按键 | 作用 |
| --- | --- |
| `Ctrl+N` / `Ctrl+O` / `Ctrl+S` | 新建 / 打开 / 保存 |
| `Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`） | 撤销 / 重做 |
| `Ctrl+F` / `Ctrl+H` | 打开查找替换 |
| `F3` / `Shift+F3` | 下一个 / 上一个匹配 |
| `Ctrl++` / `Ctrl+-` | 字号加 / 减 |
| `Tab` / `Shift+Tab` | 在编辑区插入制表符 / 切出编辑区（保持键盘导航） |
| `Esc` | 关闭查找栏 |

## 数据与状态

- 打开文件时用 `FileReader` 读取原始字节，识别编码后只在内存里解码；**不上传、不发网络请求**
- 保存时用 `Blob` + `<a download>` 触发浏览器下载，不会直接覆盖磁盘上的原文件
- 正文、撤销历史、当前文件名都不持久化，刷新或关闭页面就没了；只有字号和自动换行存在 localStorage
- 没有自动保存，也没有后台同步

## 测试

测试在仓库根目录的 Playwright 套件里（`tests/text-editor.spec.js`），随 CI 在三种环境（桌面 Chrome / Pixel 5 / iPhone 13）运行：

- **初始状态**：空文档、默认文件名、字号 16、自动换行开、撤销/重做禁用、状态栏编码/换行/字符数、灰色标题占位符可见，移动端无横向溢出
- **编辑**：输入后标题出现 `●`、占位符隐藏、撤销/重做；桌面端 `Ctrl+N` 新建时对未保存修改弹确认
- **手机顶栏**：只显示图标与短标签，顶栏高度 < 110px、文件名行 < 46px，无横向溢出
- **打开文件**：UTF-8 BOM + CRLF 文件，校验编码、换行、BOM、末尾无换行与内部 LF 规范化
- **保存**：下载文件名与 UTF-8 字节；GBK + CRLF 的字节、编码和换行
- **查找替换**：匹配计数、下一个/上一个的选区、全部替换、区分大小写、正则错误提示、`Esc` 关闭
- **偏好**：字号增减、关闭自动换行，刷新后仍保留
- **快捷键**：`Ctrl+F` 打开、`Esc` 关闭；编辑区按 `Tab` 插入制表符且不切焦点，有选区时替换选区
- **内置自检**：`?selftest` 的编码往返与 BOM 识别全部 PASS（仅桌面端）

## 已知限制（如实说明）

- **保存 = 下载**：浏览器不能直接写回原文件，每次保存都会产生一个下载文件；想覆盖原文件需要自己移动/重命名
- **没有自动保存**：页面崩溃或误关可能丢失未下载的修改，只有关闭前的确认提示
- **编码识别是启发式**：短文本、无 BOM 的 UTF-16、二进制文件可能识别错；打开后可用「重新解码」按正确编码重读原始字节
- **旧编码依赖浏览器**：GBK / Big5 / Shift_JIS / Windows-1252 的编解码依赖 `TextDecoder`；浏览器不支持某个编码时会打开失败，请先转成 UTF-8。首次用 GBK 等编码保存时要建立反查表，可能短暂停顿
- **不可映射字符会变成 `?`**：保存前会弹确认；要完整保留请用 UTF-8
- **换行符会被规范化**：编辑时内部统一为 LF，保存时再按选择转换；混合换行文件保存后会被统一，原文件的混合状态不保留
- **末尾新行不自动补**：保存的是编辑器里的实际内容；编辑器末尾有没有换行，下载文件就原样保留
- **大文件会慢**：撤销栈、状态统计、查找都对超大文本做上限保护；几 MB 以上建议用桌面编辑器
- **没有语法高亮、行号栏、多标签页、文件树**：这是单文件小工具，不是 IDE
- **原生确认框**：未保存提醒和不可映射字符确认用的是浏览器 `confirm`，样式不可定制
- 不支持 IE
- **手机端看不到完整按钮名**：窄屏只显示图标，完整名称放在 `title`（长按提示）与 `aria-label` 里；编码 / 换行下拉只显示短标签，具体编码和换行仍以底部状态栏为准

## 浏览器兼容

| 浏览器 | 最低版本 | 卡在哪 |
| --- | --- | --- |
| Chrome / Edge | 55 | `async/await`（55）、`TextDecoder` / `TextEncoder`、`Element.closest` |
| Firefox | 52 | `async/await`（52） |
| Safari | 10.1 | `async/await`（10.1）；旧编码的 `TextDecoder` 支持视系统而定 |
| iOS Safari | 10.3 | 同上 |

布局只用了 flex、`max-width` 和媒体查询，没有用 flex `gap` / `aspect-ratio` 这类抬高门槛的写法；`:focus-visible` 和 `color-scheme` 只影响观感。Firefox 未纳入 CI 测试矩阵，版本按特性支持情况推算；低于表中版本时页面可能仍能打开，但会出现排版错位或个别功能不可用。不支持 IE。
