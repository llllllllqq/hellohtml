# 身份证扫描拼接工具

把身份证正、反面两张扫描件，按**真实尺寸**排到一张 A4 上，直接打印就能用。全程在浏览器里完成，图片不会上传到任何服务器。

[idcard.html](idcard.html)（约 18 KB）就是全部代码，零依赖。

## 用法

1. 双击打开页面，分别上传（或直接拖入）身份证**正面**和**反面**
2. 两张都就绪后，「下载 JPG」「下载 PDF」才会变为可用
3. 点一下即可下载，文件名是 `身份证_A4_打印版.jpg` / `身份证_A4_打印版.pdf`

打印时请务必在打印设置里选择 **「实际大小」/「100% 缩放」**，不要勾选「适应页面」或「缩放至纸张大小」，否则打印出来的证件会比实物大或小。

## 尺寸与排版

| 项目 | 数值 |
| --- | --- |
| 证件尺寸 | 85.6 × 54.0 mm（GB 标准，第二、三代身份证） |
| 圆角半径 | 3.18 mm |
| 输出分辨率 | 300 DPI（证件 1011 × 638 px，A4 2480 × 3508 px） |
| 排版 | 两证水平居中，上下三段的留白均分（`(A4 高 − 2 × 证件高) / 3`） |
| JPG 质量 | 0.95 |
| PDF | 单页 A4（595.28 × 841.89 pt），内嵌 DCTDecode JPEG |

## 实现细节

- 用 Canvas 绘制：先填白底，再裁一个圆角矩形路径，然后按「覆盖并居中」缩放画入（`scale = max(卡宽/图宽, 卡高/图高)`），保证不拉伸、不留白边
- **PDF 是手写的**：`%PDF-1.4` → Catalog / Pages / Page / 内容流 / 图像 XObject（`/Filter /DCTDecode`）→ xref → trailer，只用 `TextEncoder` 拼字节，不引入 pdf.js、jsPDF 之类的库
- 图片用 `URL.createObjectURL` 读取，处理完立即 `revokeObjectURL`，大图不占内存
- 全局拦截了 `dragover` / `drop`，避免手滑把图片拖出上传框、导致浏览器直接打开图片

## 测试

测试在仓库根目录的 Playwright 套件里（`tests/idcard.spec.js`），随 CI 在三种环境（桌面 Chrome / Pixel 5 / iPhone 13）运行：

- 初始状态下两个下载按钮都禁用、状态栏为空
- 上传正反面后出现预览、文件名回显、按钮变为可用
- 下载 JPG：文件名正确、文件非空大于 1 KB
- 下载 PDF：文件以 `%PDF-` 开头、体积正常
- 上传非图片文件：提示「处理失败」，按钮恢复可点
- 窄屏单列 / 宽屏双列的响应式布局、横向溢出检查

## 已知限制（如实说明）

- **只做居中裁剪，不做透视校正**：拍摄歪斜、带背景、比例不对的照片，需要先用扫描类 App（扫描全能王等）裁好、摆正再上传，否则证件会被裁掉一部分
- 图片会被按卡面比例（85.6 : 54）居中裁剪，多余部分直接裁掉，不会出现黑边
- 不做 OCR，也不识别真伪，纯粹是排版工具

## 浏览器兼容

| 浏览器 | 最低版本 | 卡在哪 |
| --- | --- | --- |
| Chrome / Edge | 76 | `Blob.arrayBuffer()`（76） |
| Firefox | 69 | `Blob.arrayBuffer()`（69） |
| Safari | 14 | `Blob.arrayBuffer()`（14） |
| iOS Safari | 14.5 | 同样是 `Blob.arrayBuffer()`，iOS 上要 14.5 |

页面布局不再依赖 flex `gap`（Chrome 84 / Safari 14.1），按钮组和操作区改用子元素外边距，所以上表就是实际门槛。

`Blob.arrayBuffer()` 只在导出 PDF、把 JPEG 塞进 PDF 时用到；更老的浏览器「下载 JPG」仍然正常，只有 PDF 会提示处理失败。

Firefox 未纳入 CI 测试矩阵，版本按特性支持情况推算；低于表中版本时页面可能仍能打开，但会出现排版错位或个别功能不可用。不支持 IE。
